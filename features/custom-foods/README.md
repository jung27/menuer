# 사용자 지정 음식

- `/custom-foods`: 계정별 음식 목록, 최신순 20개씩 조회.
- `/custom-foods/new`: 음식 추가. `?edit=<id>`로 같은 편집 화면에서 수정.
- `/mypage`: 현재 계정 닉네임·이메일 조회.
- 홈과 각 화면의 프로필 버튼: 마이페이지 / 사용자 지정 음식 / 로그아웃.
- 미로그인 시 로그인 링크를 표시하며, 보호 화면 접근 시 로그인 화면으로 이동합니다.

`SensoryObject`의 `customConfig`를 그대로 사용합니다. 맛 6개, 모든 물리 속성 13개, 겉면·속면 색상 2개와 질감 종류(튀김·고기·면·밥·빵·국물·채소)를 저장합니다. 색상은 40개 팔레트와 브라우저 색상 선택기로 고릅니다. 맛 수치와 물리 수치는 독립적으로 편집합니다. `PHYSICS_FIELDS`가 원본 타입의 모든 숫자 속성을 포함하도록 타입으로 확인합니다. 이전 저장 음식에 질감 종류가 없으면 기본 고기 질감으로 불러옵니다.

그림은 PNG/JPG/WEBP를 받아 브라우저에서 최대 512px WEBP로 줄입니다. 저장 크기는 최대 350KB이고 파일 서명을 서버에서 확인합니다. 이미지와 설정은 MongoDB `custom_foods`에 저장합니다. 공개 파일 경로를 만들지 않으며, 목록·개별 조회·수정 모두 세션의 계정으로 제한합니다.

API: `GET/POST /api/custom-foods`, `GET/PATCH /api/custom-foods/:id`.
쓰기 본문: `{name,tags,physics,image}`. `tags`는 기존 한국어 맛 키를 사용하고 0~1, 물리 값은 0~1(최대 늘어남은 0.3~2), 색상은 `#RRGGBB`, image는 허용된 data URL 또는 null입니다.

사용자 지정 음식은 이번 단계에서 계정별 보관·미리보기·편집에 사용합니다. 기존 `/food-card`의 기본 음식 목록이나 서버 추천 카탈로그에 자동 편입하지 않습니다.

기존 `components/SensoryObject.tsx`와 인증·기록 API는 변경하지 않았습니다. 기존 헤더의 `UserMenu`와 로그인 후 복귀 경로만 연결했습니다. 스타일은 `ac-` 이름으로 분리합니다.
